S01 · Alta / P1

La aprobación obligatoria de escritura MCP se puede eludir con rutas alternativas

Condiciones: Sesión local con escritura automática o autoaprobación. El agente solicita un alias de una configuración protegida: ruta relativa, ~ o enlace simbólico. No se presupone que la configuración predeterminada permita autoescritura.

Impacto y causa: El control compara la ruta original, pero la escritura posterior normaliza y resuelve el destino. Se puede modificar una configuración MCP sin la aprobación adicional exigida. Los servidores de la configuración global de Warp pueden arrancar automáticamente al ser cargados.

Evidencia y límites: Trazado completo de permiso a escritura. Arnés Rust aislado con el clasificador real y un hogar sintético: la ruta directa se reconoce; config.toml relativo, ~/.claude.json y un enlace con otro nombre no se reconocen. La escritura por el alias cambia el destino protegido. No es una prueba integrada de la aplicación.

Corrección recomendada: Resolver directorio actual, ~, enlaces y padres existentes antes de autorizar. Comprobar el destino efectivo y vincular la verificación al archivo que finalmente se abre; cubrir también archivos nuevos y cambios entre comprobación y uso.

S02 · Alta / P1

El almacenamiento alternativo de credenciales usa una clave global pública

Condiciones: Linux/FreeBSD: Secret Service no está disponible o falla. El atacante obtiene una copia del archivo; otro usuario local puede leerlo si los directorios superiores son transitables y la umask permite lectura.

Impacto y causa: AES-GCM deriva siempre la misma clave de una constante incluida en el código. Quien consiga el archivo puede recuperar refresh tokens o claves BYO. La escritura genérica tampoco impone 0600; con umask 022 crea archivos 0644. La variante de permisos reforzados no se usa para login/BYO.

Evidencia y límites: Prueba con Node crypto y datos sintéticos: descifrado con la clave del fuente correcto; directorio 0755 y archivo 0644 bajo umask 022. Se trazó el registro por defecto del fallback y los callers de persistencia. No se leyeron credenciales reales.

Corrección recomendada: Eliminar el cifrado con clave global; usar protección vinculada al usuario/OS o no persistir si falta un almacén seguro. Aplicar 0700/0600 en todos los caminos, migrar archivos existentes y evaluar rotación cuando haya evidencia de exposición. Cambiar permisos por sí solo no protege copias filtradas.

S03 · Alta / P1

Kitty puede borrar archivos fuera de los directorios temporales

Condiciones: El usuario muestra salida de terminal maliciosa con Kitty habilitado, configuración predeterminada fuera de Windows. Debe existir un directorio intermedio transitable que contenga el marcador tty-graphics-protocol; otro usuario local puede crearlo en /tmp. El proceso víctima debe poder leer y borrar el destino. Un atacante exclusivamente remoto necesita un directorio apropiado ya existente o poder prepararlo.

Impacto y causa: La comprobación usa prefijos de texto y un marcador en cualquier parte de la ruta, sin resolver .. ni enlaces. read_file lee y elimina el archivo antes de validar su formato de imagen. El destino puede quedar fuera de /tmp, /var/tmp y /dev/shm.

Evidencia y límites: Se extrajeron y compilaron las funciones reales safe_delete_temp_file/is_path_in_temp_dir. Un archivo exclusivamente sintético bajo ~/.cache fue leído y eliminado mediante una ruta con .. desde el temporal: lexical_temp=true, synthetic_read=20, target_exists=false. No se ejecutó una secuencia maliciosa contra la GUI.

Corrección recomendada: Validar el directorio canónico y el nombre del archivo; evitar seguir enlaces y utilizar operaciones relativas a un descriptor de directorio validado. Mantener el control de identidad hasta el borrado. No confiar en prefijos de strings.

S05 · Alta / P1

Los enlaces externos new_tab/new_window pueden ejecutar archivos locales

Condiciones: El sistema entrega a Warp un enlace externo con path hacia un ejecutable existente. Puede haber un aviso del navegador para abrir Warp. En Unix el archivo debe ser ejecutable; en Windows los archivos .cmd/.bat/.ps1 pueden ser ejecutables sin bit Unix.

Impacto y causa: La intención de abrir pestaña/ventana llama al mismo flujo que ejecutar archivos. Se encola y ejecuta el comando al terminar el arranque del shell, sin una confirmación interna específica de ejecución. La ruta se escapa: no se demuestra inyección de argumentos.

Evidencia y límites: Trazado estático new_tab/new_window → open_file → ExecuteInSession → set_pending_command → BootstrapPrecmdDone → try_execute_command. Los tests existentes corroboran la decisión de enrutado. No se hizo reproducción GUI ni en Windows.

Corrección recomendada: Exigir que path sea directorio en estas intenciones. Separar abrir archivo de ejecutarlo, y exigir confirmación explícita para ejecutar contenido solicitado por un enlace externo.

S06 · Media / P2

MCP reenvía claves de API personalizadas al destino de una redirección

Condiciones: El usuario configura x-api-key/api-key y el servidor MCP responde con una redirección a otro origen, por ejemplo por una redirección abierta o una migración a un tercero.

Impacto y causa: El cliente instala las cabeceras como defaults y conserva la política de redirección predeterminada. Reqwest elimina Authorization en el cambio de origen, pero mantiene estas claves personalizadas, que recibe otro servidor.

Evidencia y límites: Prueba dinámica con reqwest 0.13.5 del cache, dos servidores loopback y valores ficticios: cross_origin_x_api_key_received=true; cross_origin_authorization_received=false. Se validó la biblioteca y el constructor usado; no un servidor MCP real.

Corrección recomendada: Restringir redirecciones al origen autorizado o inyectar credenciales únicamente para ese origen. Prohibir también degradaciones HTTPS→HTTP.

S07 · Media / P2

El cliente de control local envía tokens y cuerpo al proxy HTTP del entorno

Condiciones: HTTP_PROXY/http_proxy está configurado sin una exclusión efectiva de localhost en NO_PROXY. El registro de descubrimiento puede ser totalmente válido y seguir apuntando a 127.0.0.1.

Impacto y causa: Client::new honra el proxy: el bearer de cinco minutos, limitado a una acción, y los parámetros de operación pueden salir del equipo hacia el proxy. El listener sigue siendo loopback; no se demuestra control remoto ni ejecución remota de comandos.

Evidencia y límites: Prueba dinámica del constructor blocking real con un proxy loopback y token ficticio: loopback_request_sent_to_proxy=true; scoped_credential_received_by_proxy=true.

Corrección recomendada: Usar un cliente dedicado con no_proxy(), redirecciones deshabilitadas y timeout acotado. Mantener la validación del destino loopback.

S08 · Media / P2

Un enlace simbólico elude el alcance de lectura aprobado para el agente

Condiciones: AlwaysAsk con directorio permitido, o permiso temporal sobre un directorio. Existe dentro de ese directorio un enlace hacia un archivo externo; puede venir de un repositorio no confiable.

Impacto y causa: Path::starts_with acepta el alias, mientras File::open sigue el enlace. El contenido externo llega al agente sin la aprobación que correspondería a su ubicación real. No es un escape de sandbox y no amplía configuraciones que ya autorizan cualquier lectura.

Evidencia y límites: Arnés Rust local con archivos ficticios: el prefijo autorizado acepta el alias y la apertura devuelve el marcador de un archivo fuera del directorio permitido. Recorrido de permisos y lectura verificado estáticamente.

Corrección recomendada: Autorizar la identidad canónica del archivo en el sistema de archivos correspondiente y mantener la relación con el descriptor abierto; añadir regresiones de enlaces y sustituciones entre comprobación y acceso.

S10 · Media / P2

Un patrón corto personalizado debilita la redacción de secretos existente

Condiciones: Se configuran patrones que se solapan y se envía contenido mediante telemetría UGC habilitada o una petición AI con redacción habilitada. No se afirma exposición bajo los defaults aislados.

Impacto y causa: Los patrones se combinan con prioridad; find_iter devuelve coincidencias no superpuestas. Un patrón anterior que solo cubra el prefijo desplaza al patrón completo. La unión posterior no recupera la coincidencia descartada.

Evidencia y límites: Prueba Rust con regex-automata 0.4.9 del lockfile: un PAT totalmente ficticio de 40 bytes queda oculto por defecto (0..40); añadir un patrón para ghp_ solo oculta 0..4 y deja 36 bytes del secreto sintético intactos.

Corrección recomendada: Calcular la unión de coincidencias de todos los patrones, incluidas las solapadas, antes de reemplazar. Preservar por separado los niveles de prioridad y probar superposiciones parciales y totales.

S11 · Media / P2

El texto de notificaciones OSC9 se registra sin redacción

Condiciones: La salida de terminal incluye contenido sensible en una notificación OSC9. Para la salida a Sentry además deben estar activos crash reporting y un evento posterior que adjunte el breadcrumb.

Impacto y causa: El cuerpo llega a log::info antes de consultar el flag de notificaciones; se guarda localmente y puede adjuntarse a Sentry. before_breadcrumb no elimina el contenido y el scrubber mostrado solo limpia valores de excepciones.

Evidencia y límites: Trazado estático de parser → logger → breadcrumb → callback. No se provocó un envío a Sentry ni se probaron datos reales.

Corrección recomendada: Eliminar el cuerpo del log y registrar metadatos inocuos. Revisar/redactar breadcrumbs como defensa adicional; no confiar en desactivar la notificación visual.

Controles positivos observados

  • Control local: peer UID, credenciales aleatorias limitadas a acción, validación de Host/Origin y revalidación de permisos; no se encontró bypass de autenticación del servidor en lo revisado.
  • Callbacks de autenticación y MCP OAuth verifican estado pendiente; no se estableció bypass OAuth.
  • ZIP Node revisado usa enclosed_name; el actualizador macOS comprueba firma/equipo.
  • La consola project_console.rs transmite initial_directory sin interpolación de shell; no se encontró inyección en ese flujo.
  • La mayoría de acciones CI examinadas se fijan por SHA; el workflow de etiquetado pull_request_target no descarga código del PR.
